# Project State

## Current status

The repository is a mock-only Next.js/TypeScript prototype for Nevo's Personal Adaptive Academic Tutor.

The original project documents are now present under `/docs` and are the source of truth for future implementation work. Agents must read `AGENTS.md`, `BRANCH_WORKFLOW.md`, `docs/README.md`, and the relevant spec documents before changing behavior.

## What exists

- Desktop-first Hebrew RTL app shell.
- Main tutor workspace with right-side materials panel, central tutor conversation, and left-side learning status/memory panel.
- Work modes: Learning, Practice, Research, Build, Temporary Chat.
- Cost modes: Cheap Practice, Normal Learning, Deep Research.
- Mock workspace, file, learner memory, academic knowledge, tutor messages, and decision log data.
- Type-only structures for future model, retrieval, and web search providers.
- Behavior tests covering mock tutor guardrails.

## What is still mocked

- Tutor responses are generated by `getMockTutorResponse`.
- File records are static mock data.
- Learner Memory is static mock data.
- Academic Knowledge Base items are static mock data.
- Decision Log entries are static mock data.
- Retrieval routing is represented only as mock metadata.
- Provider status is represented only by TypeScript types.

## What is not connected

- Firebase Authentication.
- Firestore.
- Firebase Storage.
- Gemini.
- Genkit.
- Gemini File Search.
- Google Search Grounding.
- Real retrieval.
- Real file upload.
- Persistent learner memory.
- Server-side model calls.

## What is ready

- The repo is ready for docs-based planning and staged implementation.
- The mock prototype is ready for review against `/docs`.
- The type layer is ready to guide future provider abstractions without exposing secrets or connecting services.
- Behavior tests are ready to protect the current mock guardrails.

## What is not ready

- The repo is not ready to connect Firebase, Gemini, Genkit, retrieval, or persistent storage without a dedicated implementation plan.
- The app is not an MVP-complete tutor yet.
- Real file ingestion, retrieval budgets, memory writes, summaries, and decision logging still require implementation.

## How to run locally

1. Run `npm install`.
2. Run `npm run dev` to start the development server.
3. Run `npm run build` for a production build.
4. Run `npm run lint` for linting.
5. Run `npx vitest run` for behavior tests.
